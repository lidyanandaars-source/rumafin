# Voice interpretation hardening — 2026-10-02

This revision fixes the observed case:

`Buat akun baru bernama Bank Mandiri dengan saldo 10 juta rupiah.`

which was incorrectly persisted as `CREATE_TRANSACTION`.

## Root causes addressed

1. Structured JSON validation previously checked shape only, not semantic consistency between transcript and intent.
2. A valid-looking but semantically wrong model response could therefore stop the fallback chain.
3. Preview matching silently defaulted an unspecified transaction account to Cash and an unspecified category to Others.
4. `Number(null)` produced `0`, which made a missing transaction amount appear as `Rp0`.
5. The account prompt contained an inconsistent rule about putting all account names in `account_selector`, even for `CREATE_ACCOUNT`.
6. CREATE_ACCOUNT could reach preview without a usable account type.

## New safeguards

- Deterministic high-confidence intent hints for explicit Indonesian commands such as `buat akun`, `ubah saldo awal`, `hapus transaksi`, and transfers.
- Each provider result is normalized and semantically validated before it is accepted. A wrong result triggers the next model fallback.
- Five-level intent routing: Gemini primary → Groq GPT-OSS 120B → Groq GPT-OSS 20B → Gemini secondary → Gemini Flash-Lite.
- Safe deterministic recovery for explicit CREATE_ACCOUNT name, opening balance and account type when directly supported by the transcript.
- Preview and commit re-validate persisted commands against their original transcript.
- Missing account/category values no longer silently become Cash/Others.
- Missing transaction amounts no longer become Rp0.
- Preview now exposes `can_commit` and `blocking_issues`; the UI disables mutation when required data is unresolved.
- Commit rejects incomplete previews server-side as a second line of defense.

## Expected result for the reported transcript

```json
{
  "intent": "CREATE_ACCOUNT",
  "account_hint": "Bank Mandiri",
  "account_type": "BANK",
  "account_changes": {
    "opening_balance": 10000000
  }
}
```

The preview should show Bank Mandiri, BANK, and Rp10.000.000, then require normal confirmation before account creation.

## Deployment and verification

Deploy the three changed Edge Functions and the frontend:

```bash
npx supabase functions deploy voice-interpret
npx supabase functions deploy transaction-command-preview
npx supabase functions deploy transaction-command-commit
```

Make sure both Groq intent secrets exist:

```bash
npx supabase secrets set GROQ_INTENT_MODEL=openai/gpt-oss-120b
npx supabase secrets set GROQ_INTENT_FALLBACK_MODEL=openai/gpt-oss-20b
```

Then speak or re-enter:

`Buat akun baru bernama Bank Mandiri dengan saldo 10 juta rupiah.`

Verify the newest command in Supabase SQL Editor:

```sql
select
  created_at,
  transcript,
  intent,
  parsed_payload,
  confidence
from public.voice_commands
order by created_at desc
limit 5;
```

The new row must have `intent = 'CREATE_ACCOUNT'`. The `parsed_payload` should contain `account_hint = 'Bank Mandiri'`, `account_type = 'BANK'`, and `account_changes.opening_balance = 10000000`.

The old incorrect row is historical audit data and is not rewritten automatically. The hardened preview/commit path will reject a persisted command whose intent conflicts with its original transcript.
